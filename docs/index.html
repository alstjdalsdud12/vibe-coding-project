비전 제시 & 문제 정의

"유저가 상상하는 캐릭터를, AI가 즉시 만들고, 바로 게임을 플레이한다"

기존 RPG의 한계 (문제 정의)

  • 캐릭터는 개발자가 미리 제작한 것 중에서만 선택
  • 내가 원하는 캐릭터를 만들려면 그림 실력·설계 능력 필요
  • 모든 플레이어가 동일한 캐릭터로 게임
  • 개인화된 스토리·스킬 생성 불가능

우리의 비전 & 해결책

  • 텍스트 3줄 입력만으로 캐릭터 즉시 완성
  • AI가 스탯·스킬·배경스토리 자동 생성 (이름은 직접 입력)
  • 생성 즉시 던전 플레이 가능
  • 플레이 기록 기반 AI 소설까지 자동 생성
외형 · 무기 · 컨셉 입력 → AI가 5초 내 완성 → 바로 플레이

활용 방안

"AI와 협업하는 개발 방식 자체가 이 프로젝트의 또 다른 결과물"
ADR 요약 Architecture Decision Records · 5개
ADR-001 Unity 2D 선택 — 씬 관리·게임 루프·Android/iOS 동시 빌드 내장. Flutter·React Native는 게임 기능 없어 탈락.
ADR-002 Node.js + Express — AI·DB 라이브러리가 바로 설치 가능, 여러 요청 동시 처리에 최적. Spring은 1인 프로젝트엔 과대 설계.
ADR-003 Firebase Firestore — 서버 직접 관리 불필요, AI가 만든 캐릭터 데이터 저장 구조와 딱 맞음. 무료 티어로 충분.
ADR-004 AI 레벨업 스킬 생성 — 캐릭터 생성 시 함께 생성해 추가 API 비용 없이 컨셉 맞춤 스킬 확보.
ADR-005 GameState 정적 클래스 — 씬 전환 무관 유지, 어디서나 접근. LoadCharacter()로 캐릭터 전환 시 완전 초기화.

구현 시행착오 & 성능 최적화 & 코드 품질

시행착오 사례

① AI 생성 스킬이 빈 값으로 저장되는 버그
AI가 만든 스킬 중 일부가 이름 없이 빈 채로 저장됨 → 빈 스킬 자동 제거 로직으로 해결
② 캐릭터 바꿨을 때 이전 데이터가 남는 버그
캐릭터 교체 시 이전 캐릭터 골드·레벨이 그대로 남아있음 → 교체 감지 즉시 데이터 초기화로 해결
③ AI가 한국어에 한자를 섞어 출력하는 문제
LLM이 한국어 생성 중 한자를 자동 삽입함 → 한자 자동 감지·제거 필터로 해결

성능 최적화

  • API 요청 설정 캐싱으로 재전송 방지
  • 결과물 형식 확인 → 1회 재요청 후 기본값 사용
  • GameState 캐싱으로 불필요 API 호출 방지
  • 레벨스킬 생성 시 추가 비용 없음
