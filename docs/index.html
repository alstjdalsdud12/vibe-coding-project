  • 캐릭터는 개발자가 미리 제작한 것 중에서만 선택

  • 모든 플레이어가 동일한 캐릭터로 게임
  • 개인화된 스토리·스킬 생성 불가능

ADR 요약 Architecture Decision Records · 5개
ADR-001 Unity 2D 선택 — 씬 관리·게임 루프·Android/iOS 동시 빌드 내장. Flutter·React Native는 게임 기능 없어 탈락.
ADR-002 Node.js + Express — Groq·Firebase SDK가 npm으로 제공, 비동기 I/O에 적합. Spring은 1인 프로젝트엔 과대 설계.
ADR-003 Firebase Firestore — 서버리스, JSON 캐릭터 데이터와 NoSQL 구조가 자연 일치. 무료 티어로 충분.
ADR-004 AI 레벨업 스킬 생성 — 캐릭터 생성 시 함께 생성해 추가 API 비용 없이 컨셉 맞춤 스킬 확보.
ADR-005 GameState 정적 클래스 — 씬 전환 무관 유지, 어디서나 접근. LoadCharacter()로 캐릭터 전환 시 완전 초기화.
각 결정의 대안·이유를 .planning/decisions/ 폴더에 문서화

질의응답 준비

Q. 앱 구조는?

Unity 5씬 + Node.js 백엔드 + Firebase. 씬 간 데이터는 GameState 정적 클래스로 공유.

Q. 개발 환경 설정은?

Node.js 18 + Unity 2022.3 LTS. backend/에서 npm install, .env 키 입력 후 npm run dev.

Q. 빌드와 배포 차이는?

빌드 = 소스 → 실행파일(APK). 배포 = 실행파일을 실제 환경에 올리는 것(Railway, ADB).

Q. AI 오류 처리는?

스키마 검증 실패 시 1회 재시도. 한자 섞임은 정규식 sanitize. 최종 실패 시 기본값 반환.

Q. HP 지속성 구현은?

GameState.CurrentHp/Mp에 씬 이동 전 저장, 씬 시작 시 복원. 새 캐릭터는 풀 HP로 리셋.

Q. Firebase 선택 이유?

서버리스 · 무료 티어 충분 · JSON 캐릭터 데이터와 NoSQL 구조가 자연스럽게 일치.
