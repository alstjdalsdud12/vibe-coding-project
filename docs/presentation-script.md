> 각 슬라이드 "이번 페이지는 OOO입니다." 형식으로 시작

## 슬라이드 1 — 타이틀

"안녕하세요. 지금부터 '나만의 스토리' 프로젝트 발표를 시작하겠습니다.

이번 페이지는 프로젝트 소개 타이틀입니다.

저는 Unity 2D, Node.js, Groq AI, Firebase를 활용해서 AI가 만들어주는 나만의 RPG 캐릭터 게임을 개발했습니다."

---

## 슬라이드 2 — 비전 & 문제 정의

"이번 페이지는 비전 제시와 문제 정의입니다.

기존 RPG 게임은 개발자가 미리 만들어둔 캐릭터 중에서만 고를 수 있었습니다. 내가 원하는 캐릭터를 만들려면 그림 실력이나 설계 능력이 있어야 했고, 모든 플레이어가 똑같은 캐릭터로 게임을 했습니다.

저는 이 문제를 AI로 해결했습니다. 외형, 무기, 컨셉 세 줄만 입력하면 AI가 이름, 스탯, 스킬, 배경 스토리를 5초 안에 완성하고, 바로 게임을 플레이할 수 있습니다."

---

## 슬라이드 3 — 프로젝트 계획 & 진행 과정

"이번 페이지는 프로젝트 계획과 진행 과정입니다.

총 7주 일정으로 진행했습니다. 1·2주차에는 기획과 요구사항 정리, 백엔드 구성, Groq AI 연동을 완료했고, 3·4주차에는 Unity 씬 구성과 캐릭터 생성 UI, Firebase 연동을 마쳤습니다. 5·6주차에는 마을과 던전 씬, 전투와 레벨 시스템, AI 소설 생성을 구현했고, 7주차에 버그 수정과 문서 완성, 그리고 오늘 발표까지 마무리했습니다.

기술 선택 근거는 각각 다음과 같습니다. Unity는 씬 관리와 Android, iOS 동시 빌드가 가능하고, Node.js는 AI 라이브러리를 바로 설치할 수 있어 선택했습니다. Groq는 빠른 응답과 한국어 이해가 뛰어나고, Firebase는 서버 관리 없이 무료로 사용할 수 있습니다."

---

## 슬라이드 4 — 구현 방법 설명

"이번 페이지는 구현 방법 설명입니다.

AI 캐릭터 생성은 네 단계로 이루어집니다. 먼저 유저가 외형, 무기, 컨셉, 세계관을 입력해 서버로 전달합니다. 서버는 Groq API의 LLaMA 3.3 70B 모델을 호출하고, 결과물 형식이 맞는지 확인해서 틀리면 자동으로 한 번 더 요청합니다. 마지막으로 한자 필터링을 거쳐 Firebase에 저장합니다. 이 과정에서 이름, 스탯, 고유 스킬, 레벨 5·10·15 스킬, 배경 스토리, 던전 지역 5곳을 한 번에 만들어냅니다.

게임 시스템은 마을 씬과 던전으로 구성되어 있고, HP는 씬 전환 후에도 유지됩니다. AI 소설 생성 기능은 플레이 기록과 습득한 스킬을 분석해서 내 캐릭터가 주인공인 소설을 자동으로 만들어줍니다."

---

## 슬라이드 5 — 활용 방안 & 기대 효과

"이번 페이지는 활용 방안과 기대 효과입니다.

이 프로젝트는 AI가 게임 콘텐츠를 무한으로 생성하는 프로토타입입니다. 개발자가 캐릭터를 미리 설계하지 않아도 되기 때문에, 플레이어마다 완전히 다른 캐릭터와 스토리를 경험할 수 있습니다.

기대 효과로는 캐릭터 설계 공수를 없애고, 내 캐릭터라는 애착으로 이탈률을 줄일 수 있습니다. 향후 AI가 생성하는 퀘스트와 맵, 멀티플레이어 PVP, AI 소설 커뮤니티 공유 기능으로 확장할 수 있습니다. 그리고 Claude Code AI Agent와 협업해 1인이 7주 만에 이 모든 것을 완성했다는 것 자체가 또 하나의 결과물이라고 생각합니다."

---

## 슬라이드 6 — ADR 요약

"이번 페이지는 ADR 요약입니다. ADR은 Architecture Decision Records로, 기술 결정 근거를 문서로 남긴 것입니다.

총 5개입니다. ADR-001은 Unity 2D를 선택한 이유로, 씬 관리와 게임 루프, Android와 iOS 빌드가 내장되어 있기 때문입니다. ADR-002는 Node.js와 Express로, AI와 DB 라이브러리를 바로 설치할 수 있고 여러 요청을 동시에 처리하기에 적합합니다. ADR-003은 Firebase Firestore로, 서버를 직접 관리할 필요 없이 AI가 만든 캐릭터 데이터 구조와 딱 맞아 선택했습니다. ADR-004는 캐릭터 생성 시 레벨 스킬까지 함께 만들어서 추가 API 비용 없이 컨셉 맞춤 스킬을 확보하는 방식입니다. ADR-005는 GameState 정적 클래스로, 씬이 바뀌어도 데이터가 유지되고, 캐릭터를 전환할 때 LoadCharacter로 완전히 초기화합니다."

## 슬라이드 7 — 앱 구조 & 아키텍처 다이어그램

"이번 페이지는 앱 구조 설명과 아키텍처 다이어그램입니다.

Unity 씬은 총 5개입니다. 타이틀에서 서버 연결을 확인하고, 메인 메뉴에서 캐릭터 목록을 보고 선택합니다. 캐릭터 생성 씬에서 입력 후 API 결과를 받고, 마을 씬에서 상점과 미션, 출석을 관리합니다. 마지막 게임 씬에서 던전 전투와 레벨업, 사망 처리가 이루어집니다.

아키텍처는 3-Tier 구조입니다. Unity 클라이언트가 REST API로 Node.js 백엔드를 호출하고, 백엔드가 Groq AI와 Firebase를 연결합니다. API 키는 백엔드에만 있어서 클라이언트에는 노출되지 않습니다."

---

## 슬라이드 8 — 개발 환경 설정 & 빌드·배포

"이번 페이지는 개발 환경 설정과 빌드, 배포 과정입니다.

개발 환경은 Node.js 18 이상과 Unity 2022.3 LTS입니다. 백엔드 실행은 backend 폴더에서 npm install 후 .env 파일에 API 키를 입력하고, npm run dev를 실행하면 localhost 3000번에서 서버가 시작됩니다.

빌드와 배포의 차이를 설명드리겠습니다. 빌드는 소스 코드를 실행 파일로 변환하는 단계입니다. Unity는 APK로 빌드하고, Node.js는 별도 빌드 없이 바로 실행됩니다. 배포는 그 결과물을 실제 환경에 올리는 단계입니다. 백엔드는 Railway 클라우드에 GitHub 연동으로 자동 배포하고, 클라이언트는 ADB로 기기에 직접 설치합니다."

## 슬라이드 9 — 시행착오 & 성능 최적화 & 코드 품질

"이번 페이지는 구현 시행착오와 성능 최적화, 코드 품질입니다.

개발하면서 세 가지 주요 문제가 있었습니다. 첫 번째로 AI가 생성한 스킬 중 일부가 이름 없이 빈 채로 저장되는 버그가 있었는데, 빈 스킬을 자동으로 제거하는 로직으로 해결했습니다. 두 번째로 캐릭터를 바꿨을 때 이전 캐릭터의 골드와 레벨이 그대로 남아있는 문제는, 캐릭터 교체를 감지하는 즉시 데이터를 초기화하는 방식으로 해결했습니다. 세 번째로 AI가 한국어 생성 중에 한자를 자동으로 섞어 출력하는 문제는, 한자를 자동으로 감지하고 제거하는 필터로 해결했습니다.

코드 품질 면에서는 GitHub에 의미 있는 커밋을 30개 이상 남겼고, AGENTS.md에 AI 협업 규칙을 정리했으며, LLM Wiki에 노하우를 기록해서 지속적으로 기술을 개선했습니다."

AGENTS.md 파일 하나에 Agent 정의, Skills, Rules, Commands를 모두 통합해서 관리했습니다. Claude Code가 이 파일을 읽고 프로젝트 전반의 AI 행동 규칙을 자동으로 적용합니다.

규칙을 여러 파일로 분산하면 AI가 놓치는 경우가 생기는데, 단일 파일로 통합하면 한 곳만 수정해도 전체에 반영됩니다. 덕분에 커밋 메시지 형식이나 한국어 처리 규칙이 일관되게 유지됐습니다."

# 질의응답 준비

**Q. 앱 구조는?**
"3-Tier 구조입니다. Unity 클라이언트가 REST API로 Node.js 백엔드를 호출하고, 백엔드가 Groq AI와 Firebase를 연결합니다. Unity는 씬 5개로 구성되어 있고, 씬 간 데이터는 GameState 정적 클래스로 공유합니다."

**Q. 개발 환경 설정은?**
"Node.js 18 설치 후 backend 폴더에서 npm install, .env에 API 키를 입력하고 npm run dev로 실행합니다. Unity는 2022.3 LTS에서 game 폴더를 열면 됩니다."

**Q. 빌드와 배포 차이는?**
"빌드는 소스 코드를 실행 파일로 변환하는 단계입니다. Unity는 APK를 빌드하고, 백엔드는 Node.js라 별도 빌드 없이 실행합니다. 배포는 그 결과물을 실제 환경에 올리는 것으로, 백엔드는 Railway, 클라이언트는 ADB로 기기에 설치합니다."

**Q. AI 오류 처리는?**
"결과물 형식이 틀리면 자동으로 한 번 더 요청합니다. 한자가 섞이면 자동 필터로 제거하고, 최종 실패 시에는 기본값으로 대체됩니다."

**Q. HP 지속성 구현은?**
"씬 전환 직전에 HP를 GameState에 저장해두고, 다음 씬 시작 시 그대로 복원합니다. 새 캐릭터는 항상 풀 HP로 시작합니다."

**Q. Firebase 선택 이유?**
"서버를 직접 관리할 필요가 없고, 무료 사용이 가능합니다. AI가 만든 캐릭터 데이터 구조가 NoSQL 문서 구조와 딱 맞아 선택했습니다."
