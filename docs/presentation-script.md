# 발표 대본 — AI 기반 캐릭터 생성 2D 모바일 게임

> 총 5분 | 데모 30초 포함 | 대본 기준 4분 30초
> 각 섹션 앞의 [mm:ss] 는 누적 경과 시간

---

## [0:00] 오프닝 — 비전

"게임에서 캐릭터를 고를 때, 항상 개발자가 만들어둔 캐릭터 중에서 고르셨죠.
저는 이 방식을 뒤집었습니다.
제 프로젝트의 비전은 단 하나입니다.

**'유저가 상상하는 캐릭터를, AI가 즉시 만들고, 바로 게임을 플레이한다.'**

외형, 무기, 컨셉 세 가지만 입력하면 — AI가 이름·스탯·스킬·배경 스토리를 자동 생성하고,
그 캐릭터로 바로 던전에 들어갑니다."

---

## [0:22] 문제 정의

"기존 RPG의 문제는 개인화가 없다는 것입니다.
제가 원하는 '복수를 노리는 냉혹한 암살자'를 만들고 싶어도,
그림 실력도, 게임 설계 능력도 없으면 불가능했습니다.

하지만 AI를 쓰면 다릅니다.
텍스트 세 줄로 내 캐릭터가 완성됩니다."

---

## [0:40] 프로젝트 계획 — WBS & 기술 스택

"7주 동안 크게 네 단계로 진행했습니다.
1주-2주: 백엔드·AI 연동,
3주-4주: Unity 클라이언트,
5주-6주: 게임 시스템(레벨·스킬·마을·전투),
7주: 최종 완성 및 발표.

기술 스택입니다.
- 게임 엔진: Unity 2022 LTS — 씬 관리, Android/iOS 동시 빌드
- 백엔드: Node.js + Express — AI API 호출 중심의 비동기 I/O
- AI 생성: Groq API (LLaMA 3.3 70B) — 빠른 응답속도, 한국어 이해 우수
- 데이터베이스: Firebase Firestore — 서버리스, 무료 티어로 충분

각 기술 선택 이유는 ADR, 즉 Architecture Decision Record 5개로 문서화했습니다."

---

## [1:05] 아키텍처 & 앱 구조

"아키텍처는 3-tier 구조입니다.
Unity 클라이언트가 REST API로 Node.js 백엔드에 요청하고,
백엔드가 Groq AI를 호출해 캐릭터를 생성, Firebase에 저장합니다.
API 키는 백엔드에 격리해 클라이언트에 노출되지 않습니다.

Unity 씬 구성은 다섯 개입니다.
타이틀 → 메인메뉴(캐릭터 목록) → 캐릭터 생성 → 마을 씬 → 던전(게임 씬).
모든 UI는 프리팹 없이 C# 코드로 절차적 생성합니다.
씬 간 데이터는 GameState 정적 클래스로 관리합니다."

---

## [1:28] 구현 방법 — 핵심 기술 설명

"핵심 구현 두 가지를 설명하겠습니다.

**첫 번째, AI 캐릭터 생성.**
유저 입력이 오면 서버가 Groq API를 호출합니다.
LLaMA 3.3 70B가 이름, 스탯, 고유 스킬, 레벨 5·10·15 스킬, 배경 스토리를 JSON 하나로 생성합니다.
서버에서 스키마를 검증하고 실패하면 자동으로 한 번 재시도합니다.
한자나 일본어가 섞이는 문제는 정규식 sanitize 함수로 제거했습니다.

**두 번째, AI 소설 생성.**
레벨·전투 기록·습득 스킬을 분석해 AI가 개인화 소설을 자동 생성합니다.
초보 캐릭터는 단편, 베테랑 캐릭터는 페이지로 나뉜 장편 소설이 생성됩니다.
캐릭터의 스킬 이름이 전투 장면에 실제로 등장하도록 프롬프트를 설계했습니다.

**세 번째, 게임 시스템.**
마을 씬에서 상점·미션·출석 체크·원정대·가방을 제공합니다.
던전에서는 5구역 탐험, 전투(공격·스킬·아이템·도망), XP·레벨업, 사망 시 캐릭터 영구 삭제가 동작합니다.
HP는 던전과 마을 씬 사이에서 지속 유지됩니다."

## [1:58] 개발 환경 & 빌드·배포

"개발 환경은 Node.js 18, Unity 2022.3 LTS, Git입니다.
백엔드는 .env 파일로 API 키를 관리하고, npm run dev로 실행합니다.

빌드와 배포를 구분하면 —
빌드는 소스 코드를 실행 파일로 변환하는 단계입니다.
Unity는 Android SDK를 타겟으로 APK를 빌드하고,
백엔드는 Railway 같은 클라우드 플랫폼에 배포합니다.
GitHub README에 단계별 설치 가이드를 작성해두었습니다."

## [2:20] 구현 시행착오 & 최적화 & 코드 품질

"시행착오가 세 가지 있었습니다.

첫째, **null 스킬 역직렬화 버그.**
JsonUtility가 null 배열 요소를 기본값 객체로 만들어 이름 없는 스킬이 생겼습니다.
RemoveAll 필터로 해결했습니다.

둘째, **GameState 오염.**
캐릭터를 전환할 때 이전 캐릭터의 골드·레벨이 새 캐릭터에 이어졌습니다.
LoadCharacter()에서 ID 변경을 감지해 전체 초기화하는 방식으로 해결했습니다.

셋째, **한자 섞임.**
LLM이 한국어 텍스트에 한자를 자연스럽게 섞었습니다.
정규식으로 한자 유니코드 범위를 제거했습니다.

성능 최적화로는 Groq API 시스템 프롬프트 재사용과 서버사이드 스키마 검증 재시도를 구현했습니다.
코드 품질 관리는 Claude Code를 통해 26개 이상의 의미 있는 커밋을 유지하고,
AGENTS.md 단일 파일에 Agent 정의·스킬·규칙·커맨드를 통합 관리합니다."

## [3:42] 활용 방안 & 마무리

"이 프로젝트의 핵심 가치는 **AI가 게임 콘텐츠를 무한 생성**한다는 것입니다.
개발자가 캐릭터를 직접 설계하지 않아도 됩니다.

향후 발전 방향으로는
AI가 생성하는 퀘스트와 스토리, 멀티플레이어 PVP,
그리고 캐릭터 AI 소설을 공유하는 커뮤니티 기능을 생각하고 있습니다.

마지막으로, 이 프로젝트는 Claude Code라는 AI Agent를 적극 활용해
1인 개발로 7주 만에 완성했습니다.
AI와 협업하는 개발 방식 자체가 이 프로젝트의 또 다른 결과물입니다.

감사합니다."

## 질의응답 준비 (ADR 요약)

| ADR | 결정 | 이유 한 줄 |
|-----|------|-----------|
| ADR-0001 | Unity 2D | 씬 관리·모바일 빌드·게임 루프 내장 |
| ADR-0002 | Node.js + Express | AI/DB SDK npm 제공, 비동기 I/O 적합 |
| ADR-0003 | Firebase Firestore | 서버리스, JSON 구조와 NoSQL 자연 일치 |
| ADR-0004 | AI 레벨스킬 생성 | 캐릭터 컨셉 반영, 추가 API 비용 없음 |
| ADR-0005 | GameState 정적 클래스 | 씬 전환 무관 유지, 어디서나 직접 접근 |

**예상 질문 & 답변:**

Q. 앱 구조는 어떻게 되어 있나요?
A. "3-tier 구조입니다. Unity 클라이언트 — Node.js 백엔드 — Firebase Firestore. Unity는 타이틀·메인메뉴·생성·마을·던전 씬 5개로 구성됩니다."

Q. 개발 환경 설정은 어떻게 하나요?
A. "Node.js 18 설치 후 backend 폴더에서 npm install, .env에 API 키 입력, npm run dev. Unity는 2022.3 LTS와 Android Build Support 모듈 설치 후 game 폴더를 열면 됩니다."

Q. 빌드와 배포 단계는?
A. "빌드는 소스 코드를 실행 파일로 변환하는 단계입니다. Unity는 File→Build Settings→Android→Build로 APK를 생성합니다. 배포는 생성된 APK를 기기에 설치하거나, 백엔드를 Railway 같은 클라우드에 올리는 단계입니다."
