## [0:05] 슬라이드 2 — 비전 & 문제 정의

"게임에서 캐릭터는 항상 개발자가 만들어둔 것에서 골라야 했습니다.
내가 원하는 캐릭터를 만들려면 그림 실력이 필요했고, 없으면 불가능했습니다.

저는 이걸 뒤집었습니다.
외형·무기·컨셉 세 줄만 입력하면, AI가 캐릭터를 완성하고 바로 게임을 플레이합니다."

---

## [0:40] 슬라이드 3 — 프로젝트 계획 & 진행 과정

"7주로 진행했습니다.
1·2주차 백엔드와 AI 연동, 3·4주차 Unity 클라이언트, 5·6주차 게임 시스템, 7주차 마무리입니다.

기술 스택은 Unity, Node.js, Groq AI, Firebase이고,
각 기술 선택 이유는 ADR 5개로 문서화했습니다."

---

## [1:10] 슬라이드 4 — 구현 방법

"캐릭터 생성은 네 단계입니다.
유저 입력 → Groq API 호출 → 스키마 검증 → Firebase 저장.
이름, 스탯, 레벨 5·10·15 스킬, 배경스토리를 한 번에 만들어냅니다.

게임은 마을 씬과 던전으로 구성되고, HP는 씬 간에 유지됩니다.
AI 소설은 플레이 기록을 분석해 자동으로 생성됩니다."

---

## [1:50] 슬라이드 5 — 활용 방안 & 기대 효과

"이 프로젝트는 AI가 게임 콘텐츠를 무한 생성하는 프로토타입입니다.
개발자가 캐릭터를 설계하지 않아도 됩니다.
향후 AI 퀘스트, 멀티플레이어 PVP, 소설 공유 커뮤니티로 확장할 수 있습니다."

---

## [2:15] 슬라이드 6 — ADR 요약

"기술 결정 5가지를 ADR로 문서화했습니다.
Unity는 씬 관리와 Android 빌드, Node.js는 AI SDK와 비동기 I/O,
Firebase는 서버리스와 JSON 구조 일치, LLaMA는 빠른 응답과 한국어 이해,
GameState 정적 클래스는 씬 간 데이터 공유 때문에 선택했습니다."

---

## [2:45] 슬라이드 7 — 앱 구조 & 아키텍처

"아키텍처는 3-Tier입니다.
Unity가 REST API로 Node.js 백엔드를 호출하고, 백엔드가 Groq AI와 Firebase를 연결합니다.

씬은 타이틀·메인메뉴·캐릭터생성·마을·던전 다섯 개이고,
디렉토리는 backend, game, docs 세 영역으로 분리되어 있습니다."

---

## [3:15] 슬라이드 8 — 개발 환경 & 빌드·배포

"개발 환경은 Node.js 18과 Unity 2022.3 LTS입니다.

빌드는 소스 코드를 실행 파일로 변환하는 단계, 배포는 그걸 실제 환경에 올리는 단계입니다.
Unity는 APK로 빌드하고, 백엔드는 Railway에 배포합니다."

코드 품질은 커밋 30개, ADR 5개, AGENTS.md로 관리했고,

# 질의응답 준비

## ADR 5개 (외워서 답변)

| ADR | 결정 | 이유 한 줄 |
|-----|------|-----------|
| 001 | Unity 2D | 씬 관리·Android/iOS 빌드 내장 |
| 002 | Node.js + Express | AI·DB SDK npm 제공, 비동기 I/O |
| 003 | Firebase Firestore | 서버리스, JSON 구조와 NoSQL 일치 |
| 004 | AI 레벨스킬 생성 | 추가 API 비용 없이 컨셉 맞춤 스킬 |
| 005 | GameState 정적 클래스 | 씬 전환 무관, LoadCharacter로 초기화 |

## 예상 질문 답변 (외우기)

**Q. 앱 구조는?**
"3-Tier 구조입니다. Unity 클라이언트 — Node.js 백엔드 — Firebase. Unity는 씬 5개, 디렉토리는 backend, game, docs로 분리됩니다."

**Q. 개발 환경 설정은?**
"Node.js 18 설치 후 backend에서 npm install, .env에 API 키 입력, npm run dev로 실행합니다. Unity는 2022.3 LTS에 game 폴더를 열면 됩니다."

**Q. 빌드와 배포 차이는?**
"빌드는 소스 코드를 실행 파일로 변환하는 단계입니다. Unity는 APK를 빌드하고, 백엔드는 Node.js라 별도 빌드 없이 실행합니다. 배포는 그 결과물을 실제 환경에 올리는 것으로, 백엔드는 Railway, 클라이언트는 ADB로 기기에 설치합니다."
