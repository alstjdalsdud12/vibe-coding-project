## 슬라이드 3 — 프로젝트 계획 & 진행 과정

"이번 페이지는 WBS와 기술 스택입니다.

7주 일정으로, 1·2주차 백엔드·AI 연동, 3·4주차 Unity 클라이언트, 5·6주차 게임 시스템, 7주차 마무리 순으로 진행했습니다. Unity는 씬 관리와 모바일 빌드, Node.js는 AI 라이브러리 즉시 사용, Groq는 빠른 응답, Firebase는 서버 관리 불필요 때문에 선택했습니다."

## 슬라이드 4 — 구현 방법 설명

"이번 페이지는 구현 방법입니다.

유저 입력 → Groq API 호출 → 스키마 검증 → Firebase 저장, 네 단계로 스탯·스킬·배경 스토리를 한 번에 생성합니다. 이름은 유저가 직접 입력합니다. 게임은 마을과 던전으로 구성되고, HP는 씬 전환 후에도 유지됩니다. 플레이 기록 기반 AI 소설도 자동 생성됩니다."

Unity는 씬 관리·모바일 빌드, Node.js는 AI SDK 즉시 설치, Firebase는 서버리스·JSON 구조 일치, AI 레벨스킬은 추가 비용 없이 생성 시 함께 만들고, GameState 정적 클래스는 씬 전환 시 데이터 유지를 위해 선택했습니다."

# 질의응답

**Q. 앱 구조는?**
"3-Tier 구조입니다. Unity — Node.js 백엔드 — Groq AI·Firebase. 씬 5개, 씬 간 데이터는 GameState 정적 클래스로 공유합니다."

**Q. 개발 환경 설정은?**
"backend에서 npm install, .env에 키 입력, npm run dev. Unity는 2022.3 LTS에서 game 폴더를 열면 됩니다."

**Q. 빌드와 배포 차이는?**
"빌드는 소스를 실행 파일로 변환, 배포는 그걸 실제 환경에 올리는 것입니다. Unity는 APK 빌드 후 ADB 설치, 백엔드는 Railway 자동 배포입니다."

**Q. AI 오류 처리는?**
"형식이 틀리면 1회 자동 재요청, 한자는 필터 제거, 최종 실패 시 기본값으로 대체합니다."

**Q. Firebase 선택 이유?**
"서버 관리 불필요, 무료 사용 가능, AI 캐릭터 JSON 구조와 NoSQL이 자연스럽게 일치합니다."
